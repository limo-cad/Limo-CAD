# Authored lesson geometry

The 58 CBOR v1 lesson bundles contain 236 display frames for Sketch and Solid
guidance. Opening them does not execute OCCT or create a CAD document. The
editable workflows live in the 27 bundled recipes selected by the Help catalog,
including `examples/scripts/extrude-basics.limo.jsonc`.

Generate with the native geometry SDK configured:

```sh
cargo run --locked --manifest-path mcp-server/Cargo.toml --example generate_show_me -- --out desktop/assets/show-me
```

The generator executes each distinct recipe once, validates its assertions and
typed frames, removes passive sketch snapping aids, and stores both Cut outcomes
in six frames. Use `--recipe BUNDLED_ID` to regenerate one recipe. Each envelope
contains version, lesson identity, the SHA-256 of the recipe with LF line endings,
and frames. No camera raster or live-document state is stored. The limit is 2 MiB
per file, 8 MiB total; decoded geometry must also pass normal preview budgets.

`native_script_preview_bundled_assets_match_source_and_geometry_budgets` checks
all assets, source freshness and geometry budgets without running the recipe or
creating a renderer. Regenerate whenever the recipe or exported DTO semantics
change, then rerun the native visual/geometry evidence. Geometry generated by
different kernel versions/platforms is not assumed to have identical binary IDs.

`provenance.json` records the generation source revision, completed recipe checks,
frame counts, byte sizes and asset hashes. The checked-in set was regenerated by
the native engine in [CI run 40000395956](https://github.com/limo-cad/Limo-CAD/actions/runs/40000395956).
Its source and geometry-budget tests passed; recordings and interaction checks
remain separate qualification evidence.
