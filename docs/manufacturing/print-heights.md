# Height intent

Height intervals and variable layer profiles belong to the same print-intent document as part settings and local modifiers. Project schema 14 stores print-intent version 4. Earlier projects migrate with empty height collections and no invented settings. Newer versions are rejected rather than silently discarded.

The initial scope is a stable body definition: every intentional visible occurrence inherits its request. A binding uses the existing assembled scene or a saved named layout's immutable UUID, all resolved occurrence poses, exact visible multipart membership, and printable group Z bounds from transformed mesh vertices. The mechanical model and joints are unchanged. A legacy named layout acquires its identity only through the existing owned Save/update path; reading or binding height intent never assigns an identity.

Settings-only intervals explicitly choose object-bottom Z or build-plate Z. They use the same five typed process settings as other scopes, plus closed optional outer-wall, inner-wall and infill speed fields. Touching intervals are permitted; conflicting overlaps are rejected after converting both coordinate systems to resolved print Z. Variable layering is a separate opt-in with increasing object-bottom samples starting at zero and ending at the captured object height. Persistence does not assert that these values satisfy an unknown printer's limits.

An ordinary update retains the captured binding. Changed geometry, orientation, placement, visibility, group membership or deleted layouts produce actionable stale-binding reports. `print_intent_rebind_height` is an explicit transaction: it returns old and new binding evidence and optionally accepts corrected interval values or variable samples. Cross-kind corrections are rejected. Values are never clamped or silently reinterpreted.

Shared engine and MCP operations are `print_intent_height_binding`, `print_intent_upsert_height_range`, `print_intent_upsert_layer_profile`, `print_intent_remove_height` and `print_intent_rebind_height`. Every write requires the exact current `expected_model_json` under the owning engine lock. Pending loads/recomputes reject metadata writes. Project persistence and existing metadata history keep geometry unchanged and preserve the source namespace and monotonic identity allocation. Deleted attachments remain explicit orphan metadata and cannot be assigned to an unrelated body.

Portable 3MF and STL omit slicer process metadata and print-only settings. The Bambu saved-project adapter checks the selected owning layout identity and actual exported poses, quantities, multipart membership and mesh bounds. Bambu ranges and variable layering operate on the entire native object; sibling volumes and intentional native instances must request equivalent intervals/settings or profiles. Partial body-only edits to a multipart group fail with a scope explanation.

Settings-only native ranges include the unchanged effective template layer height. Variable profile constraints come from the supplied complete template: selected filament/nozzle mapping, minimum/maximum heights, initial height, supports and plate compatibility. Native minimum/maximum vectors must match the physical nozzle count; the current adapter conservatively requires samples to fit every physical nozzle, including possible support extruders. Organic support and rafts are rejected; prime-tower plate schedules must agree. The adapter preserves unrelated native metadata and retains typed baseline/written height snapshots through the existing stable volume UUID and instance identify bindings. Unknown managed keys, conflicting baseline ranges or unexpected native height edits require review. Refresh does not guess identities from object order or names.

Deterministic writer fixtures cover two distinct multipart objects sharing a prime-tower plate: matching variable schedules are retained, differing schedules and variable/fixed mixtures produce actionable errors, and fixed-only output remains usable. Rejected requests keep their authored schedules unchanged. Separate regressions exercise both supported organic-style spellings and raft rejection. These checks establish adapter compatibility decisions; they do not qualify gantry clearance or change print sequence.

Capability reporting distinguishes stored requests, applied metadata, installed-slicer import and generated toolpaths. Bambu Studio 2.8.2.61 is qualified for typed interval settings, three role speeds and variable profiles under the constraints above. OrcaSlicer remains unsupported for this target-project adapter until separately qualified. Representation support does not assert that a particular project's settings were exported or sliced successfully.

Retained acceptance fixtures exercise upright and horizontal repeated multipart groups through ten actual-writer packages. Installed Bambu imported, sliced and saved all ten with exit zero. Independent G-code checks found requested 12/14/16 mm/s outer-wall/inner-wall/sparse-infill extrusion feeds inside the band, finer upper layers and additional local-modifier walls after range application. Native-save readback matches complete normal/modifier triangle geometry, grouping and quantities within 0.001 mm and retains height metadata. The first scalar-speed probe failed despite metadata retention: the X2D profile uses six extruder variants. That failed probe is retained alongside the corrected qualification.

Automatic refresh requires preserved stable UUID/instance-identify pairs. A native save that rewrites intentional repeat instance identities requires explicit reviewed rebinding; neither geometry order nor names authorize a guessed refresh.

When a same-document saved archive still embeds an obsolete CAD manifest, clearing a saved handoff alone does not reset automatic refresh. The separate **Start reviewed native baseline** action requires complete manually reviewed CAD occurrence-to-native volume/instance bindings. Its default-false `start_reviewed_native_baseline` request rejects an accompanying refresh reference, adopts the inspected archive's current settings as a new baseline, and participates in the guarded preview/write review. Selecting another template/handoff or completing the write clears that consent. Existing source/target/group, profile, height and modifier validation remains required; baseline adoption does not promise that every native edit is representable. Ordinary refresh still rejects missing or ambiguous stable identities.


## Bevy editing and qualification

The existing Print Settings card exposes print-Z interval and separate variable-layer scopes. It edits requested wall/infill/shell values, three optional speeds, explicit coordinates/endpoints, individual layer samples, names and enable flags. Blank settings/speeds inherit; zero remains explicit. Length fields use document units while role speeds are explicitly mm/s. Saved-layout choices use existing stable view identities; an old view must be saved once before it can be selected. Creation lets the owning engine assign the request UUID.

Rebind is a separate reviewed action. The card shows current and previous group bounds, members, occurrence placements and orientation, and permits explicit interval/sample correction without changing names, enable flags or settings. Ordinary Apply retains the old binding. Stale snapshots, changed review inputs and dirty drafts reject atomically; adopting a saved request refreshes the capture before another request can be created.

An explicit group-copy review follows the existing hierarchy's transitive membership: a repeated definition connecting multiple printable groups includes every affected group's members in the proposal. The review lists body/group/occurrence identities, layout, requested fields and numeric semantics before one guarded document mutation. Copies receive new UUIDs, retain the source UUID and preserve unrelated records. Existing target requests are replaced only through explicitly selected UUIDs. Incompatible bounds/profile endpoints report a correction requirement; they are never clamped or inferred from names.
