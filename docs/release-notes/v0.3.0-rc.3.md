Limo CAD **0.3.0-rc.3** introduces the native Bevy interface. It replaces the
unpublished `v0.3.0-rc.1` and `v0.3.0-rc.2` candidates, whose release runs
stopped before publication. It includes the modeling, assembly, drawing, printing, CAM and MCP work integrated
since [0.2.2](https://github.com/limo-cad/Limo-CAD/releases/tag/v0.2.2).

> **Pre-alpha release candidate.** Keep backups of important projects. This is a
> prerelease; it does not replace the latest stable download.

## Release pipeline repairs

The [`v0.3.0-rc.2` release run](https://github.com/limo-cad/Limo-CAD/actions/runs/39917475155)
built all five packages, but its advisory gate stopped publication when
[CVE-2026-85091](https://nvd.nist.gov/vuln/detail/CVE-2026-85091), published by
NVD on **2026-09-03**, matched zlib 1.3.2 `z.dll` in both Windows packages
during the **2026-10-23** scan. That scan reported no fixed version; it does
not establish when the advisory entered Grype's database. The rc.2 binary
inspection found no `gz*` imports, and every Windows package build now repeats
that check, failing on a new zlib consumer, a `gz*` import or a second zlib copy. The [dependency review record](https://github.com/limo-cad/Limo-CAD/blob/v0.3.0-rc.3/docs/security/dependencies.md)
records that evidence, owner `@jackControls` and review deadline **2026-11-06**.
The temporary exception lists only the rc.2/rc.3 x64 and ARM64 directories;
unlisted future versions receive no exception, and unreviewed high/critical
matches still block. The record also links [upstream commit `df84af25`](https://github.com/madler/zlib/commit/df84af25dc1942490e1d1c899a07619152a46148)
and [zlib PR #1320](https://github.com/madler/zlib/pull/1320) as unverified
investigation inputs. A fix must be verified before adoption. Because the SBOM
omits vcpkg port revisions, a patched `1.3.2#N` port may retain the scanner
identity and need a renewed scoped decision until that identity changes.

The same run's first macOS attempt stapled its ticket, then lost the connection
to Apple's ticket service while validating it. Ticket validation, in packaging
and in the workflow's signature check, now gets the same bounded retry as
stapling.

Earlier, PR #524 repaired the [previous candidate's release run](https://github.com/limo-cad/Limo-CAD/actions/runs/39742586413), which
completed both Windows builds and their runtime checks, but GitHub's attestation
action rejected the Windows extended-length path prefix as a wildcard. Release
inventory outputs now use normal drive or network-share paths for all signed
subjects. The archive contents and verification requirements are preserved.

That run also lost its connection to Apple's ticket service after notarization
was accepted. macOS packaging now retries that specific stapling failure up to
four attempts, with bounded delays, and validates the attached ticket before
continuing. Other errors still fail immediately.

## What changed since 0.2.2

**Native interface** — PR #124 integrates the Rust and Bevy workspace, menus,
selection and annotations, sketch constraints, feature editing, assemblies,
drawings, print layouts and CAM controls. The interface includes native file
dialogs, multiple documents, recovery, undo/redo, localized text and
operating-system integration.

**Modeling and interchange** — PR #124 includes the large STEP import repair,
feature and picking fixes, drawing projection and annotation repairs, print
layout and slicer handoff corrections, and editable bench, vise and turbine
examples. Geometry remains OpenCASCADE based; project files retain their
parametric model and imported source geometry.

**MCP and input** — the packaged executable provides local stdio MCP and can run
headlessly. Native computer control is an explicit opt-in capability; normal
release packages ship with OS input control disabled. Session ownership,
revision boundaries, cancellation and data preservation checks remain enabled.

**Build and release engineering** — PR #124 carries the Rust maintenance tools,
native platform package checks, dependency inventories and signed source-bound
release evidence. CI efficiency work (#384) prepares the Windows SDK once per
MCP workflow and shares one acceptance definition between platforms.
Prerelease packages use numeric Apple bundle versions and Debian's prerelease
ordering while retaining the complete version and revision in the executable.

**Sketch and feature editing** — subsequent fixes (#428, #433, #434) consolidate
sketch interaction and macOS stability repairs, correct nested profile selection,
merge selected Extrude/Revolve profiles, and restore the original model state
while editing a history feature.

**Materials and thermal studies** — PR #513 adds physical material response,
unit-aware properties and persistent thermal-study data. PR #512 keeps sketch
parameter and dimension edits atomic when validation fails.

**Desktop reliability and trust** — PR #518 strengthens MCP client and process
boundaries, PR #509 updates the application icon, and PR #522 updates TLS
certificate trust dependencies.

## New since the rc.2 candidate

**Editable DXF dimensions** — PR #511 exports linear, angular, radial and series
dimensions as editable DXF dimensions. It keeps aligned versus projected intent,
saved precision, labels and presentation. When editable coordinates cannot
reproduce the saved value, the export falls back to complete graphical output.

**Complete project snapshots** — PR #514 keeps model and domain data together
through editing, Undo/Redo, tab eviction and restore, Save/Open and live
publication. Snapshots are committed under document ownership and revision
checks. Supported legacy archives open before strict snapshot validation, and
re-saving keeps their intent and extra archive entries.

**Portable project replay** — PR #515 adds an editor for a project's portable
replay source. Run executes it in a new design from the saved baseline,
leaving the original design and archive unchanged. Source and baseline survive
editing, draft recovery and save/reopen.

**Dependencies** — PR #523 updates compatible Rust and CodeQL dependencies
together (libc 0.2.191, zip 9.0.5, CodeQL actions 4.39.0) and adds checks that
keep AccessKit, Parley, widget text and Windows graphics types aligned with
Bevy 0.20. Breaking Bevy-family upgrades are deferred to a coordinated
migration. PR #528 updates arboard to 3.7.0, find-msvc-tools and the MCP
server's jsonschema; PR #527 updates the Rust CI cache action to 2.9.3.
PR #529 records the local crate versions that #514 left at `0.3.0-rc.2` in the
workspace lockfiles.

## Qualification and known gaps

Targeted automated checks cover native interface contracts, geometry and MCP
acceptance, packaged startup and platform behavior. The complete manual surface
UI and MCP qualification ledger, and the full three-model human UI walkthrough,
remain unfinished. Release builds do not establish universal gesture timing or
physical pinch qualification. Startup experiments implemented for the retired
web/Tauri shell are retained as reference material rather than active native UI.

Project snapshots keep unknown domains opaque. They exclude active sketch state
and derived results, and script export of legacy projects that carry domain
data remains blocked. Physical keyboard typing in the replay source editor is
not qualified. The shutdown issue tracked in #374 remains open; this build adds
bounded shutdown diagnostics but does not fix it.

## Project compatibility

The `.limo` ZIP container remains version 1; the current model schema is 15.
The native project reader recognizes legacy `.nbcad` project archives and legacy
format identities. Projects saved by this build can also carry domain
snapshots and portable replay source; earlier candidates were not tested
against them. Older builds may reject projects saved with newer model features
or schema revisions. Preserve an original copy when upgrading.
