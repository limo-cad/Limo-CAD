Limo CAD **0.3.0** brings the native Rust and Bevy desktop interface to the
official release channel. It includes the modeling, assembly, drawing, printing,
CAM and MCP work integrated since
[0.2.2](https://github.com/limo-cad/Limo-CAD/releases/tag/v0.2.2), plus fixes made
after the [rc.3 preview](https://github.com/limo-cad/Limo-CAD/releases/tag/v0.3.0-rc.3).

> **Pre-alpha software.** Keep backups of important projects. The official
> release designation does not freeze project formats or establish suitability
> for production modeling, manufacturing or physical performance.

## What changed since 0.2.2

**Native desktop and Limo identity** — PR #124 replaces the earlier web/Tauri
desktop with a Rust and Bevy workspace. Native menus, file dialogs, multiple
documents, recovery, undo/redo, localized text and operating-system integration
share the same document engine used by MCP. New projects use `.limo`; legacy
project readers retain compatibility. PR #509 updates the application icon.

**Modeling and assemblies** — PR #124 integrates sketch constraints, feature
editing, assembly controls, picking and large STEP import repairs, plus editable
bench, vise and turbine examples. Subsequent fixes (#428, #433, #434) improve
sketch interaction, nested profile selection, combined Extrude/Revolve profiles
and restoration of the original model while editing a history feature. PR #512
keeps sketch parameter and dimension edits atomic when validation fails.

**Drawings and editable DXF** — PR #124 adds native drawing and annotation
workflows. PR #511 exports supported linear, angular, radial and series
dimensions as editable DXF dimensions, preserving aligned/projected intent and
saved labels. Unsupported dimension formats fall back to complete graphical
output, including basic frames, tolerances, dual units, precision above eight
places and labels or coordinates that cannot reproduce the saved value.

**Materials, manufacturing and CAM** — PR #513 adds unit-aware physical material
properties and persistent thermal-study data. PR #124 includes print layout,
slicer handoff and early CAM controls. These features do not qualify physical
fit, strength, machining safety or finished-part performance.

**Complete project snapshots** — PR #514 keeps model and domain data together
through editing, Undo/Redo, tab eviction and restore, Save/Open and live
publication. Snapshots are committed under document ownership and revision
checks. Supported legacy archives open before strict snapshot validation;
re-saving preserves their intent and extra archive entries.

**Portable project replay** — PR #515 adds an editor for a project's portable
replay source. Run executes it in a new design from the saved baseline. Source
and baseline, including unfinished source drafts, are saved together in a
separate `.limo.replay.cbor` package. The original design and archive are preserved.

**Local MCP and process boundaries** — the packaged executable provides stdio
MCP and can run headlessly. PR #518 strengthens client and process boundaries.
Normal packages ship with OS input control disabled; session ownership,
revision checks, cancellation and data preservation guards remain enabled.

**Release engineering** — PR #124 introduces native platform package checks,
dependency inventories and signed build evidence tied to the source. PRs #524 and
#526 repair Windows attestation paths and bounded macOS notarization-ticket
retries. Release checks retain checksum, package identity, current dependency
advisory and reviewed-exception requirements.

## New since rc.3

**Isolated project preview** — PR #516 previews a saved project package on a
detached host without changing the open document. It reuses native teaching
playback, preserves supported body/occurrence visibility and placement, and
supports cancellation, failure recovery and resource release on Close. Shared
interpreter limits bound cumulative data and work; they are not a whole-process
memory limit and cannot interrupt a synchronous kernel call. Preview covers
geometry and assembly, with mixed assembly/inspection placement rejected.

**Shared drafting foundation** — PR #517, incorporated through #516, persists
typed layers, line types, blocks and attributes, references, curves and paper
viewports with stable IDs and atomic edits. Layer locks, native history/owner
checks and browser dispatch share the same rules. Sheet/layer deletion errors
identify blocking objects and explain recovery. Unsupported paper output rejects
with guidance. Full drafting authoring controls, rendering/reference resolution
and interchange remain separate work. Saving now writes model schema 16; see
the compatibility notice below.

**Sketch and Solid guides** — PR #432 adds 58 focused Show me guides with 236
authored frames in English, Spanish, German and Simplified Chinese. Native
playback supports Pause, inline Instructions, step navigation, Resume, Replay
and Close. Cached transitions, Point grips and dimension callouts share the
native teaching renderer. [Walkthroughs and measurement limits](../media/show-me-foundations/README.md)
record the exercised component and keyboard paths; they do not establish
physical-input, all-platform or full manual coverage. The broad UI/MCP survey
remains paused; current qualification is limited to scoped checks.

**Saved Views** — PR #525 makes clicking a saved-view name activate it, with a
separate pencil action for editing. Unfinished edits survive rejected switches
and asynchronous Save/Recall completion. Views reconcile after Print Settings
changes and metadata Undo/Redo. Activate, Discard and unsaved-edit feedback are
localized in English, Spanish, German and Simplified Chinese.

**Patched desktop zstd dependency** — PR #532 moves KTX2 decoding to zstd 0.14.3,
zstd-safe 8.2.0 and zstd-sys 2.1.2 through a manifest-only patch to the published
Bevy image crate. The native decoder remains selected. Dedicated valid/corrupt
zstd-compressed KTX2 fixture coverage remains outstanding; dependency checks do
not establish that decoding qualification. PR #533 updates the workflow actions.

**Dependency and process-inspection updates** — PR #538 supersedes the closed
#534 dependency update. It retains exact ZIP 9.1.2 with the reviewed end-of-directory
protections while avoiding later eager count-based allocation. Process inspection
handles sysinfo 0.40.1 initialization failures before deployment or owned-process
actions; the optional desktop memory probe retries when initialization is
unavailable, without inferring memory pressure.
This does not establish a hard ZIP constructor-memory bound for large valid
directories.

**Stable finish selection on supported deletion** — PR #539 prevents a later
chamfer from silently moving to another edge when its preceding fillet is deleted.
For a healthy unchanged prefix followed by two final active same-body finishes,
native copy correspondence preserves and rewrites the intended selection before
an atomic commit. Independent retained bodies and sketch Undo/Redo survive.
Connected outputs and unsupported consumers reject without guessing. General
topology naming, arbitrary consumer remapping, suppression and reorder remain
outside this bounded correction.

**Historical sketch support during parameter edits** — PR #539 validates retained
support at the sketch's original history prefix, fixing chamfer edits after a
Combine consumed that face. Validation includes the contributor's supplied model
on Windows and constructed native regressions on Windows, Linux and macOS.
This does not establish physical Kubuntu/GUI qualification or diagnose the
separately reported intermittent red-feature event. Thanks @shroffrishabh for
the reports, video and model in #536 and #537.

**Recovery after failed solid recompute** — PR #540 removes only the provisional
history feature owned by a cancelled or rejected solid transaction. The current
history cursor and unrelated interleaved sketches are preserved; successful
commits clear provisional ownership. Native failure-injection and history tests
cover refresh, archive reopen, export and retry. The original private supplier
geometry's Boolean/tessellation failure remains undiagnosed. The same change
repairs the checked OCCT runtime path for macOS native library unit tests.

## Qualification and known gaps

The rc.3 release completed its five-platform package pipeline at its recorded
revision. Those results do not substitute for this release's final package
checks. The full manual UI/MCP qualification ledger and three-model human UI
walkthrough remain unfinished. Physical keyboard input, gesture timing and
device/display coverage are limited to their recorded tests. The Bevy browser
application remains under development.

The macOS shutdown issue in #374 remains open. The second packaged desktop
stalled after its close receipt in a November 9 package check. A retry of the
same source passed; no cause or repair is established. Final-package lifecycle
evidence and a fix or explicit release risk acceptance remain required.
Physical keyboard typing in the replay source editor is also not qualified.

PR #541 adds first-frame offset-plane tests and an owned native reproduction
tool. Its Windows captures show create, edit, Undo/Redo, hide/show and reopen
working for the recorded build. The original delayed-visibility report #383
remains unreproduced and open. API captures can request redraw, so this does not
qualify passive wake delivery, physical input or Kubuntu behavior. See the
[evidence and source identities](../media/offset-plane-383/README.md).

Project snapshots preserve unknown domains as opaque data. They exclude active
sketch state and derived results, and script export of legacy projects carrying
domain data remains blocked.

Before publication, dependency decisions and any temporary exceptions must be
reviewed for the actual 0.3.0 packages. See the
[dependency review record](https://github.com/limo-cad/Limo-CAD/blob/v0.3.0/docs/security/dependencies.md)
for version-specific evidence and limits.

## Project compatibility

The `.limo` ZIP container remains version 1. Every save writes model schema 16,
including projects without drafting content. Supported schemas 1–16 load, and
the reader recognizes legacy `.nbcad` archives and format identities. Older
schema-15 readers reject newly saved files; preserve an original copy when
upgrading. Projects can carry domain snapshots; portable replay source and its
baseline use separate `.limo.replay.cbor` packages.
